# 연속 곡선 회피 20cm 후보

`--continuous20`은 기존 정지·회전·직진 방식과 분리된 후보 모드다.
차체 외곽 기준 여유 0.20m를 검사하며, 측정 불확실성과 예측 이동을 추가로 반영한다.
모든 스캔 점과 알려진 상자 경계를 유지한다. 근거리 반환을 무시하는 필터는 없다.

정적 스캔에서 곡선 후보를 생성하고 정수 RPM 주행을 재현한다. 실행 중에는
매번 최신 입력과 1초 이동 영역을 재검사한다. 전진 속도 상한은 0.025m/s,
각속도 상한은 0.2rad/s, 바퀴 상한은 10RPM이다. 작은 회전 반경에서는
안쪽 바퀴 역회전이 허용되지만 차체 중심은 전진한다.

실제 map 경로의 10cm/10도 이내 정렬을 1초 이상 확인한 뒤 Pure Pursuit로
연속 전환한다. 이후 실제 map 경로에서 1m 진행을 확인해야 완료로 기록한다.
입력 유효기간 0.8초와 모터 피드백/응답 감시는 그대로 유지한다.
안전 정지는 속도 완화 없이 즉시 적용한다. 기존 작업 공간 제한도 유지한다.

## 적용 순서

기존 후발 모터 드라이버를 종료하고 같은 환경에서 다음으로 재시작한다.

```bash
python3 -B ~/follower_diagnostics/follower_drive_node.py \
  --run-hardware --ack-hardware-zero-rpm-tx \
  --input-kind local_avoidance --ack-bounded-pivot-candidate \
  --ack-continuous20-candidate --enable-motion-input \
  --trial-max-rpm 10 --trial-seconds 360
```

다른 터미널에서 양쪽 정지 상태로 조회한다.

```bash
python3 -B ~/follower_diagnostics/run_local_avoidance_trial.py \
  --plan-only --apf-pivot --gentle-pivot --map-rejoin \
  --continue-follow-after-rejoin --continuous20 \
  --pose-source filtered --seconds 360
```

이 모드에는 `--near-return-hold`를 함께 쓰지 않는다. 명령 토픽은
`/follower/motor_candidate/continuous20_command`로 분리된다.
기존 Preview/Gateway는 계속 종료 상태로 유지한다.

## 검증 범위

기록 스캔 재생과 메모리 모터 모델, 계약/회귀 검사에 통과한 구현 후보다.
정적 스냅샷은 이동 중 새로 보이는 장애물과 실제 위치 추정 오차를 증명하지 않는다.
실물 연속 회피와 추종 전환은 아직 미검증이며 `evaluation_pass`는 false다.

계산 예산은 정지 상태에서 최대 60초다. 예산 소진은 CONTINUOUS_PLANNING_BUDGET_EXCEEDED로 구분한다. 출발 직전에도 연속 경로를 20cm 정책과 3cm 추가 여유로 재검사한다.

## 20cm 계획 / 10cm 주행 정지 기준

사용자 요청에 따라 연속 모드의 현재 차체 및 예측 이동 영역 정지 기준을 0.10m로 분리했다. 계획 목표 0.20m와 정적 후보 추가 여유는 유지한다. 불확실성은 여유에서 차감하며 입력/모터 감시는 그대로다. 드라이버 status의 continuous_stop_clearance_m=0.1이 없으면 시작을 거부하므로 드라이버 재시작이 필요하다. 정지가 없어지는 보장은 아니다.

## 복귀 후 추종 목표 거리

연속 모드의 Tracked Pure Pursuit lookahead를 0.80m에서 0.35m로 조정했다. 회피 경로와 map 복귀 안내, 10cm/10도 검증 기준 및 작업 공간은 그대로다. 기존 모드는 0.80m를 유지한다. 기록 복귀 오차(-6.6cm, -6.5도), 0.2초 자세 지연, 정수 RPM 및 액추에이터 지연을 넣은 직선 50초 모델에서 기준 이내 복구를 확인했다. 실제 지도 굴곡/AMCL 오차를 재현하는 모델은 아니므로 실물 검증이 필요하다. 드라이버 변경은 없다.

## 연속 모드 근거리 반환 재관측

연속 모드는 STOP_FOOTPRINT_CLEARANCE 발생 시 양쪽 정지를 요청하고 후발에 0 명령을 유지한다. fresh armed 모터 피드백의 RPM=[0,0] 및 3회 영속도 확인 후 서로 다른 스캔 5회에서 현재 여유 >=20cm, 검사된 여유 >15cm를 요구한다. 확인 완료 주기도 0 명령이며 다음 주기에서 입력과 이동 영역을 다시 검사한다. 최대 2초/시험당 2회, 그 외 실패는 기존 종료 조건을 유지한다. 점 삭제·입력 시각 변경·자동 재무장은 없다. 이 기능은 연속 모드에 기본 적용되며 기존 --near-return-hold는 계속 사용하지 않는다. 드라이버 변경은 없다.

## 스캔·오뎀 동기 회복

연속 모드는 filtered 오뎀과 스캔 동기 실패 시 양쪽 정지를 요청하고 최대 0.4초 동안 새 측정 쌍을 기다린다. 과거 0.2초 초과 공백은 계속 보간하지 않는다. 유효한 새 쌍과 후발 영속도 피드백 3회를 확인한 후 속도 램프를 0에서 다시 시작한다. 원래 0.8초 입력 유효기간 및 모터 watchdog은 유지한다. 복구하지 못하면 FILTERED_SCAN_ALIGNMENT_TIMEOUT으로 종료한다.

## 추종 명령 상한 반올림 수정

추종 속도 비례 축소에서 0.025000000000000005가 생기는 경우를 재현했다. 출력 단계에서 0.025로 명시 제한하며 드라이버의 엄격한 상한 검사는 유지한다. 거부 시 motion/v/w/여유/측정 시각을 기록한다. 이전 INVALID_LOCAL_AVOIDANCE_ENVELOPE 로그에는 실제 거부값이 없어 단일 원인으로 확정할 수 없다. 드라이버 재시작으로 새 기록 코드를 반영한다.

## 전방 회피 시작 80cm

차체 앞끝 x=0.27m에서 전방 0.80m 이내, 기존 좌우 폭 ±0.65m에서 5점 이상을 세며 주행 중 서로 다른 스캔 3회 감지 후 정지/계획으로 전환한다. 센서 원점이나 차체 중심 기준 80cm가 아니다. 연속 모드 초기 계획도 같은 감지 조건을 사용한다. 계획 여유 20cm/정지 10cm는 유지하며 전체 스캔을 계획과 예측 이동 영역 검사에 그대로 사용한다. 기존 실행 명령으로 적용되고 드라이버 재시작은 필요 없다.

## 최신 전방 감지 거리: 70cm

사용자 요청으로 FRONT_TRIGGER_M을 0.70m로 변경했다. 차체 앞끝 기준이며 5점/서로 다른 3개 스캔 감지, 계획 20cm, 주행 정지 10cm, 전체 스캔 충돌 검사는 유지한다. PATH_TIP_DIRECTION_MISMATCH 오류는 이 설정과 별개이며 시작 위치 복원 후 선두 Bridge 경로 이력을 재시작해야 한다.

## 회피 중 map 관측 연속성

DirectedPathTracker가 회피 초반 호출되지 않아 이전 선택 이후 누적 이동을 20cm 단일 좌표 점프로 오인하는 구조를 수정했다. 연속 모드에서는 매 제어 주기 map continuity와 위치 관측을 갱신한다. 마지막 경로 선택 이후 확인한 이동량은 누적해 진행량 제한에 사용하며, 각 관측의 20cm 점프 검사 및 경로 세션 불변 검사는 유지한다. 기존 map 시간/위치 연속성 검사도 유지한다. 드라이버 변경은 없다.
