# 후발 거리 환산 조사 — 읽기 전용 분석

## 확인된 현재 구현

- PID216 decoder는 <hBihBi 구조의 signed int16 두 속도값을 반환한다.
  firmware에서의 물리 단위/설정값을 이 구조만으로 입증할 수는 없다.
- MotorCore는 이 값을 wheel RPM으로 가정하고 v=RPM*2*pi*.065/60으로 계산.
  M1 부호 반전, M2 유지. 별도 감속비/거리 보정계수 없음.
- 새 유효응답 수신시간의 dt를 사용. .25초 초과 공백 적분 건너뜀.
  우측 끝값 적분이며 샘플 사이 실제 회전량은 직접 측정하지 못한다.
- PID216 위치값은 파싱하지만 odom에 사용하지 않는다. 위치값의 단위/PPR/
  감속비를 확인하지 않은 채 encoder count라고 가정해 대체하면 안 된다.

## 제조사 자료 조사

- https://www.mdrobot.co.kr/program-communication 에서 RS485/RS232 공식 사양서
  링크 확인. Google Drive https://drive.google.com/file/d/1n9jZexVmjpyT_lGQIhbAzJql6ix77np5/view
  는 브라우저 도구에 본문이 노출되지 않아 PID216 상세표를 확인하지 못함.
- https://www.mdrobot.co.kr/QA/?bmode=view&idx=11974838 의 제조사 답변은
  모터 모델에 맞는 극수/encoder PPR/MAX RPM 설정 확인 필요를 안내함.
  해당 답변의 MDH100 수치를 현재 후발 모터 값으로 적용하면 안 됨.
- MD200T는 제어기 모델이며 현재 연결된 실제 모터 모델/감속비/encoder
  명판 값은 작업공간 기록에서 확인하지 못함. 사용자 실물 문자 확인 필요.
- 장치 설정 읽기/쓰기나 추가 모터명령 송신을 이번 조사에서 수행하지 않음.

## 공식 PDF 확보 후 확인

- 사용자 download_mdrobot_reference.py 실행으로 공식 링크 PDF 5,176,487bytes 확보.
  Ghostscript txtwrite로 로컬 분석. 문서 표기는 RS485,232 통신사양 V6.4h.
- PID4는 읽을 PID를1byte로 요청. PID216은14/16bytes,속도signed int16 RPM,
  위치signed long. 위치에엔코더16384counts/rev를직접적용한다는근거는없음.
- 문서 PID79 Type3 표기는 MDH100(20p,300rpm,4096CPR).
  사용자400RPM 및기술지원400RPM 자료와차이있음. preset쓰지않고실저장값확인.
- Hall1 PID21,Hall2 PID65;값0~5는4/8/10/12/2/6극,
  그외값은극수/2. 엔코더 PID156(2bytes),모터2 PID170(모델/firmware지원확인필요).
  maxRPM PID221(2bytes)/모터2 PID122(2bytes),통신watchdelay PID185(2bytes,.1초단위).
- read_md200t_settings.py: PID4 allowlist만송신,쓰기/속도/0RPM/ENABLE/리셋없음.
  포트독점검사,최초및각항목뒤PID216으로fresh0RPM확인. NO_REPLY는unknown.
  원시바이트/부호있는값과없는값/송신패킷JSON보관. 실제실행아직안됨.
  query/parser/byte송신거부/기본no-open5개+기존포트13개=18/18모의통과.
