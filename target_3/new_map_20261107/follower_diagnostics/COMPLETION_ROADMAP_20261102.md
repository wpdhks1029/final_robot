# 완료 범위와 남은 단계

## 현재 완료한 범위

- 지도/초기위치/TF/leader odom·path/follower odom 연결.
- 명시적 1회 arm, 최대10RPM/30초 제한, 데이터기한·epoch·보호정지.
- 직진·좌회전·우회전 각30초 성공 기록. 선두명령0.04m/s, 회전±0.03rad/s.
- Ctrl+C 수동중단 후 양쪽영속도 확인.
- 전방상자 보호정지: 진단여유29.9cm, 사용자실측약27cm, 양쪽영속도·정지후오류없음.
- 수신 초기공백 개선 조건: Wi-Fi절전OFF, 선두bridge20Hz, START안내후30초대기.
- SDK 저장패킷 형식전환 충돌 재현 및 별도 후보 수정. 고정8비트후보 실물시작 확인.

## 현재 진행한 제한 시연을 마무리하기까지

1. 기준구성과 재시작 절차 정리: 파일 준비 완료. CURRENT_BASELINE_20261102.md와 새 follower_position_fixed_lidar.launch.py.
2. 다음 전체 재기동에서 새 시작 구성이 중복노드 없이 재현되는지 확인. 통합launch는 모의검사했으며 실물로 새 통합launch를 시작한 기록은 아직 없다. 현재 정상노드를 임의 종료하지 않는다.
3. 재기동 후 기존0.04m/s·10RPM·30초 조건으로 최종통합시연1회와 양쪽정지확인. 이미 통과한 전방장애물시험을 필수 재시험으로 추가하지 않는다.

즉 파일정리 이후 남은 것은 재시작 재현과 최종통합시연 두 단계다. 이는 현재의 제한 시연 구성에 대한 완료 기준이며 일반 환경에서 시간제한 없이 추종하는 최종운용 완료와 다르다.

## 일반환경 연속운용에 남은 별도 단계

- 뒤쪽판 없이도 유효한 라이다 입력을 확보. 순간근거리값은 원본체크섬 통과패킷에 실제존재하며 광학잡음표시는0. SDK충돌수정이 이를 제거하지 않는다. 임의 각도mask·한점무시필터 미적용.
- 30초1회시험을 넘어서는 명시적 운용상태/정지/재시작 설계 및 장시간 기록 검증. 현재 상한을 조용히 늘리지 않는다.
- 선두입력 소실 등 고장조건에서 실제 정지 반응 검증. 메모리계약검사와 실제하드웨어검증을 구분한다. 통신망 물리단절 시 선두측 정지까지 보장된 것으로 기재하지 않는다.

## 사용자 요청으로 보류한 보정

실물 직진편향, 미세한 지도/스캔정합, 회전중 정밀간격. 보정완료로 표시하지 않는다.

## 새 후발 센서 시작 명령

다음 전체 재시작 시, 후발 모터피드백이 실행되고 이전 센서/EKF/단독라이다가 종료된 상태에서:

```bash
ros2 launch ~/follower_diagnostics/follower_position_fixed_lidar.launch.py enable_position_profile:=true
```

이 명령은 원래 position profile의 IMU·EKF·TF를 유지하고 원래라이다만 끈 채 수정후보를1개실행한다. 자동arm/이동명령/모터포트접근은 없다. 기본 enable_position_profile=false이면 시작하지 않는다. 기존 시작명령은 롤백용으로 보존한다.


최신 업데이트: 통합센서 구성으로 판 없는 직진30초 성공(logs/joint_follow_trial_1793621988255863710.jsonl). 양쪽zero/오류없음, 지도간격1.391→1.549m. 순간라이다검출해결로 간주하지 않는다. 전체재부팅 재현은 아직 미실시이며 RESTART_ACCEPTANCE_20261102.md를 사용한다.


최신 제한시연 재검증: joint_follow_trial_1793624385286758908.jsonl 직진30초 시간만료/양쪽영속도확인/정지후오류없음. 주행중 INPUT_REJECTED 기록 0건. 경로이력초기화수정적용후결과. 현재기동구성의재현기록이며 일반환경장시간운용·라이다순간점·실물직진편향해결로간주하지않는다.
