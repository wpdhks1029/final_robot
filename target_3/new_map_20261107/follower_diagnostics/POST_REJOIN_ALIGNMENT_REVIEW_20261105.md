# 복귀 후 추종 분석 및 다음 관찰

대상: logs/local_avoidance_trial_1793865762811694697.jsonl

## 확인 사항

- 동적 장애물 감지, 회피 및 map 경로 복귀 후 FOLLOW 전환은 확인됐다.
- FOLLOW 전환의 local x=3.7277m, 작업 공간 끝 x=4.5m이므로 이상적인 추종에서도 남은 x 공간은 약 0.77m다. 1m 진행을 확인하려면 별도 시험 배치/허용 공간 검토가 필요하다. 현재 제한은 변경하지 않았다.
- FOLLOW 초반 map/filtered 고정 기준 방향 차이는 약 12.2도, 마지막은 19.9도다. 이것만으로 map 또는 filtered 중 어느 쪽이 실제 방향과 일치하는지는 확정할 수 없다.
- 마지막 선택 구간의 경로 방향은 5.23도지만 인접 구간은 약 11~15도다. 짧은 경로 구간의 방향 변동도 검증 실패에 영향을 준다. 기존 검증 기준은 변경하지 않았다.

## 가상 비교

analyze_post_rejoin_tracking.py가 기록된 map/filtered 변환 오차 변화를 가상 운동에 가산해 추종 이득 후보를 비교한다. 기록된 로봇의 물리 재현은 아니며 작업 공간도 모델에 포함하지 않는다.
Pure Pursuit에 방향 보정 이득 1~4/m를 추가한 후보 모두 엄격한 1m 정렬 유지 결과를 확보하지 못했다. 따라서 이득 변경은 실제 제어기에 반영하지 않았다.
결과: logs/post_rejoin_heading_comparison.json

## 다음 단계

watch_follow_alignment.py --seconds 20은 양쪽 정지/후발 비무장 상태에서 측정 시각을 맞춰 map↔filtered SE(2) 변환의 변화량을 관찰한다. 0.2초 초과 구간은 보간하지 않고 0.8초 유효기간을 유지한다. 발행/서비스/arm/자동 보정은 없다.
정지 상태에서도 변환이 흔들리면 위치 추정부터 확인하고, 정지 시 안정적이면 이동 중 시간 동기와 곡선 주행 오뎀을 추가 비교한다. 단일 관찰로 실제 방향 정확도나 물리 안전을 판정하지 않는다.

## 정지 관찰 결과 및 이동 진단

follow_alignment_1793866470647809729.json: 195개 측정 쌍, 19.4초 동안 변환 yaw span=0도, translation 변화는 수치 오차 수준이었다. 정지 상태에서의 고정 변환을 확인했을 뿐 이동 중 정합 정확도를 증명하지 않는다.

이동 관찰: watch_follow_alignment.py --seconds 90 --observe-motion. 발행/서비스/arm 없이 map/filtered 동기 변환과 raw/filtered/IMU/map 회전량을 저장한다. Ctrl+C로 끝내도 파일을 저장한다.

별도 시험: 기존 continuous20 명령에 --follow-only --follow-check-seconds 20을 추가하고 --seconds 360을 유지한다. 드라이버 360초 계약을 바꾸지 않고 운영자가 후발 arm 이후 20초에 양쪽 정지·disarm을 수행한다. 장애물 감지 시 회피 계획으로 넘어가지 않고 FOLLOW_CHECK_OBSTACLE_DETECTED로 종료한다. 진단의 정상 종료는 FOLLOW_CHECK_TIME_LIMIT이며 회피 또는 평가 통과 판정이 아니다.

## 현재 위치에서의 짧은 추종 진단 기준 수정

사용자가 위치 복원 없이 시행할 수 있다고 안내했지만, 저장된 직선 기준을 강제하는 초기 검사 때문에 두 번 PREFLIGHT_SAVED_REFERENCE_LIVE_ALIGNMENT_MISMATCH가 발생했다. 해당 관찰은 motor armed=false/RPM=0으로 이동 데이터가 아니다.
연속 follow-only 진단만 현재 live path의 가까운 유효 구간을 기준으로 초기 좌표를 정한다. 경로 거리 15cm/방향 20도, 선두 전방 및 방향 검사, 세션/역방향 검사는 유지한다. 저장 계획 파일은 수정하지 않는다. 일반 회피 모드의 저장 기준 검사도 유지한다.
관찰 도구에는 motion_sample_count와 NO_MOTION_OBSERVED 사유를 추가했다. 드라이버 재시작/Bridge 재시작/pose 초기화 없이 20초 진단을 다시 실행할 수 있다.

## 직선 이동 데이터 및 동기 회복 버그 수정

follow_alignment_1793867160802669628.json의 실제 이동 구간 약 16.60초를 동일 시각으로 재계산했다. raw -6.23도, filtered -2.77도, IMU -4.76도, map -2.89도다. 이 직선 구간 map/filtered 변화 차이는 약 0.12도다. 물리 각도 기준값은 없어 어느 센서도 자동 보정하지 않았다. 기록 전체의 SE(2) translation 변화 7.19cm는 좌표 변환 성분이며 그대로 차체 위치 오차로 해석하지 않는다.

종료는 데이터 부재가 지속된 것이 아니라 바퀴 감속 및 영속도 3회 확인이 0.548초 걸렸는데, 같은 0.4초 동기 회복 타이머에 포함돼 발생했다. 데이터 대기 0.4초, 측정 정지 확인 2초, 전체 회복 최대 2.4초로 분리했다. 기다리는 동안 양쪽 0 요청을 유지하며 실제 정지와 최신 유효 입력 없이는 재개하지 않는다. 기존 입력/모터 TTL과 보간 최대 간격은 유지한다.
관찰 요약은 raw/IMU뿐 아니라 네 소스의 공통 시작/끝을 사용하며 실제 이동 구간 비교도 따로 저장한다. 기존 요약의 SOURCE_GAP_OR_WINDOW_MISMATCH는 이 파일에서는 경계 시각 차이로 발생했다.
