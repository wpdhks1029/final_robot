# 임시 우회 경로 + Pure Pursuit 비교 후보

## 간격 기준 정정과 짧은 접근 후보

사용자는 1m를 선두 뒤끝~후발 앞끝의 빈 공간이라고 명확히 확인했다.
이 구간 안에 앞면1.3m 상자를 배치하라는 이전 안내는 폐기한다.
새 개발 배치: 후발 앞끝~상자 앞면 .60m, 상자 길이 .20m, 상자 후면~선두 뒤끝 .20m.
상자 중심은 현재 진행 기준 왼쪽 .35m, 높이는 실제 .25m 스캔 평면을 확실히 통과하게 한다.
후발 front_extent=.27m 기준 상자 전면의 기준 x는 약 .87m다.

이전 STOP_APPROACH_TOO_SHORT는 긴 다항식 접근 후보만 구현된 상태의 제한이었다.
이를 전체 물리적 불가능의 증거로 해석하지 않는다. 고정 .5m 접근 길이 거부 대신 짧은 두 원호 S자 후보도 전체 차체 검사한다.
양 바퀴 전진 조건과 외측 바퀴 10RPM 상한을 계획 추종 계산에 반영했다. 보호 거리 .30m는 유지한다.

`simulate_temporary_detour.py --one-meter-gap`: 상자·벽의 정적 가상 환경에서
통과/재합류/이후1m 기하 확인. 실제 선두의 움직임은 모의하지 않으므로 완전한 두 로봇 시험이 아니다.
실제 계획 조회는 원본 모든 스캔 점을 계속 검사하므로 선두가 막고 있으면 경로 생성이 거부될 수 있다.
약70도까지의 S자 자세가 포함될 수 있다. 기존 원래 경로 추종의45도 정렬 조건과 단순 연결해서 주행하면 안 된다.
임시 경로 추종 제어를 기존 leader 정지/간격/만료 조건과 별도로 결합하는 작업은 아직 수행하지 않았다.

이번 배치에서 실행할 조회:

```bash
python3 -B ~/follower_diagnostics/check_temporary_detour.py --seconds 10 --confirm-obstacle-visible --obstacle-center-y 0.35
```

이전 절의1.3m 배치는 긴 접근 모의의 조건으로만 남기며, 현재1m간격 실물 시험에는 사용하지 않는다.

사용자가 APF와 비교하기 위해 명시적으로 요청한 새 방식이다. 보고서의 APF 구현과 구분한다.
APF 및 기존 하드웨어 제어 연결은 교체하지 않았다. 새 파일은 순수 계산과 조회 전용이며 모터 제어에 연결되지 않았다.

## 계산

- 실제 선두 path를 주축 방향/최대 잔차로 직선 근사한다. 짧은 개별 선분 각도 잡음 대신 전체 형상을 검사한다.
- 원래 직선, 후발 pose, 실제 scan/장착 TF를 같은 기준으로 변환한다.
- 분리된 장애물 군집은 대상 추정에만 사용한다. 모든 스캔 점을 차체 충돌 검사에 포함한다.
- 확인된 20cm 상자의 보이지 않는 후단/폭을 보수적으로 채운다. 일반 장애물용 자동 형상 추정이 아니다.
- 5차 곡선의 측방 이동 → 평행 통과 → 직선 복귀 → 복귀 후 1.2m 경로를 후보로 만든다.
- 전체 사각 차체, 30cm 여유, 추가 2cm 계획 여유, 샘플 사이 병진/회전 이동 상계, 전진 바퀴 곡률을 검사한다.
- 통과 가능한 후보가 없으면 정지 결과만 반환한다. 보호 거리나 미검출 점을 변경하지 않는다.
- Pure Pursuit lookahead .25m, 단조 경로 진행, 추종 오차 .15m 초과 정지. 이는 후보 개발 조건이지 보고서 합격 기준이 아니다.

## 검증

관련 단위 검사 87개 통과. 가상 2.5m 폭 공간·상자 앞면 기준 x=1.6m, y=.25~.45m의 정적 기하에서
기존 .30m 정지/.60m 감속 및 1초 회전 차체 검사를 적용한 모의 주행:
`SIMULATED_PASS_REJOIN_PLUS_1M`, 최소 여유 .3391617m, 가상 시간293.3초.
0.04m/s 속도와 현재 감속 정책의 결과이며 30/60초 안에 전체 회피가 완료된다는 의미가 아니다.
정적 점과 알려진 상자 형상만 사용했으며 동적 물체, 가림, 위치 오차, 통신 지연, 접촉0회 실물 판정을 대체하지 않는다.

재현: `python3 -B ~/follower_diagnostics/simulate_temporary_detour.py`
결과: logs/temporary_detour_simulation.json

## 실제 데이터로 계획만 확인

양쪽 정지, 기존 노드 유지, 상자 높이는 25cm 스캔 평면 위로 확보한다.
개발 배치: 후발 차체 앞끝~상자 앞면1.3m, 공간중심보다 상자중심 왼쪽.35m. 선두와 겹치면 안 된다.

```bash
python3 -B ~/follower_diagnostics/check_temporary_detour.py --seconds 10 --confirm-obstacle-visible --obstacle-center-y 0.35
```

이 도구는 scan/pose/path/TF만 구독한다. 원본/수신 시각 .3초 검사를 유지하고 path는 원격50ms 여유를 보수적으로 차감한다.
ROS 구독을 종료한 뒤 정지 스냅샷으로 계획하여 executor를 긴 계획 연산으로 막지 않는다.
reference 잔차, 경로점, 선택방향, 경로와 원본 관측을 logs/temporary_detour_check_*.json에 저장한다.
기존 주행 시험을 실행하면 현재 APF 제어가 실행될 수 있다. 새 경로의 실제 제어 연결은 아직 구현/검증하지 않았다.
