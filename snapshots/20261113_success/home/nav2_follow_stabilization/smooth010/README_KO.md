# 연속 속도 추종 후보

## 총 세션 시간 제한 해제: 2026-11-13

start_follower_driver.bash와 start_follow.bash는 모두 0초(총 시간 무제한)를 사용한다.
기존 드라이버와 추종 프로그램을 중지한 뒤 두 프로그램을 다시 실행해야 적용된다.
드라이버 재시작은 오뎀 기준을 초기화하므로 후발 실제 위치를 RViz에서 재설정한다.
6분이 지나도 입력이 정상이고 Goal이 진행 중이면 같은 arm 세션을 유지한다.
Goal 종료, Ctrl+C, 모터/입력 오류는 기존과 같이 정지한다. Goal 종료 후 자동 재무장은 하지 않는다.

무제한은 자동 Nav2 추종에서만 허용한다. 드라이버와 운영 프로그램이 시간 정책을
서로 다르게 쓰면 시작하지 않는다. 명령·피드백·응답 0.3초, 원본 입력 시각 검사,
10초 참조 복구 대기, 엔코더/기기 상태 오류 검사는 유지한다. 바이트 전송 gate도
무제한 개방하지 않고 신선한 명령·피드백이 있을 때만 0.3초씩 갱신한다.
세션 로그에는 session_unlimited=true, trial_seconds=0을 기록한다.

변경 전 326개 파일은 ../backups/smooth010_before_unlimited에 보존했다.
무제한 동작은 가짜 시계·모터와 가짜 ROS로 360초 초과 구간을 검증한다.
이 변경의 실제 기체 시험은 수행하지 않았다.


## 간격 경계 수정: 2026-11-12

후속 실행 local_avoidance_trial_1794474797934316704.jsonl에서
SMOOTH_GAP_HOLD가 16개 기록됐다. 기록된 최근 위치를 대조한 간격은 약
1.47~1.49m였다. 목표 1.5m보다 몇 cm 짧다는 이유로 작은 선두 속도를
음의 간격 보정이 모두 상쇄했다. 초기 모형이 실제 경계 부근의 민감도를
충분히 검증하지 못했다.

수정 후 목표 간격 주변 ±0.05m에서는 간격 보정을 하지 않는다. 밖에서는
경계를 넘은 양만 연속적으로 보정한다. 1.48m이고 필터링한 선두 속도가
0.006m/s라면, 이전 목표는 0이고 새 목표는 0.006m/s이다. 속도 하한을
강제하는 변경이 아니므로 실제 선두가 정지해 속도가 0이면 정지는 가능하다.
근접 정지 한도와 회전/후진/센서 오류 정지는 그대로다.

다음 로그에는 smooth_speed 항목으로 실제 간격, 원시/필터링한 선두 속도,
간격 보정량, 목표 속도와 최종 제한 속도를 함께 남긴다. 화면의 '여유'는
라이다 장애물 여유이며 로봇 사이 간격이 아니다.

이번 수정은 후발 코드만 변경했다. 선두 설치나 모터 드라이버 재시작 없이
후발 추종 프로그램을 같은 start_follow.bash 0.1 명령으로 다시 실행하면 된다.
변경 전 코드는 ../backups/smooth010_gap_hold_1794474797934316704에 보존했다.

실제 성공 로그 local_avoidance_trial_1794473279407088944.jsonl에서는 제어 기록
1,487개 중 FOLLOW_WAITING_LEADER가 721개, 주행/정지 전환이 174번이었다.
모터의 zero_reply_hold_active 기록은 10개였다. 주된 제어 정지는 선두 속도
보고에 따른 정지 판정이다. 선두의 실제 속도가 왜 낮아졌는지까지 확정한 것은 아니다.

성공한 speed010 코드/로그 325개를
../backups/follow_010_success_1794473279407088944에 보존하고 해시를 검증했다.
기존 speed010은 변경하지 않았다. 이 후보는 smooth010에만 있다.

## 바뀐 동작

선두의 보고 속도가 순간적으로 0이 되더라도 신선한 경로/위치와 충분한
간격이 있으면 즉시 후발 속도를 0으로 만들지 않는다. 대신 다음 목표를 사용한다.

```
오차 = 현재 간격 - 1.5m
간격 보정 = 0.5 × sign(오차) × max(0, abs(오차) - 0.05m)
목표 속도 = 필터링한 선두 전진속도 + 간격 보정
```

목표 속도는 0~0.1m/s로 제한한다. 실제 정지한 선두 뒤로 접근할 때도 간격이
줄어들면 목표 속도가 연속적으로 낮아진다. 필요한 경우 0까지 감속한다.
선두 속도 필터는 원본 측정 시각이 갱신될 때만 갱신한다.

출발/일반 속도 변경에는 가속 0.12m/s², 감속 0.20m/s²의 명령 변화율을 적용한다.
PP 조향 곡률은 유지하고, 최종 15RPM 제한 결과를 다음 계산과 선두 gate에 반영한다.
후발 가속 초기의 작은 속도 요청 때문에 선두까지 정지하지 않도록 최대
0.04m/s의 출발 제한을 적용한다. 선두 Nav2의 실제 명령을 강제로 올리지는 않는다.
일반 추종 시 선두에 후발 요청보다 0.003m/s를 더 허용하던 여유는 새 모드에서만
제외해 불필요한 간격 증가를 줄인다.

아래 정지는 즉시 적용하며 완만한 감속으로 늦추지 않는다.

- 입력 만료/누락과 경로 추적 오류
- 근접 간격 제한
- 선두 회전/후진 대기
- 모터/피드백 오류, Goal 종료, 운영자 종료

기존 원본 시각과 0.8초 입력 제한, 선두 gate의 기존 시간 제한은 그대로다.
입력 복구 후에는 이전 주행 속도를 재사용하지 않고 0부터 가속한다.
사용자 선택의 후발 장애물 거리 정지 해제 상태는 유지한다.
--smooth-follow는 선택 옵션이며 최소 속도 강제 옵션과 함께 쓸 수 없다.

## 검증

- regression.log: 관련 회귀 검사 199개 통과
- deployment_test.log: 설치 파일 보존/검증 시험 1개 통과
- smoothing_flow_tests.log: 실제 PP/속도 계산을 가짜 ROS 흐름에 연결하여
  가속, Goal 종료, 입력 복구 후 0부터 재출발을 확인
- straight_model_comparison.json: 1차원 직선 가정 모형에서 비교

명시한 모형(100ms 측정 지연, 10Hz 측정, 매 세 번째 선두 속도 보고 0,
0.15초 응답 지연)에서는 이동 구간 주행/정지 전환이 기존 336회에서 0회로
줄었다. 간격 경계 수정 후 새 모형 간격은 약 1.553~1.584m였다. 초기 간격 1.45/1.8m,
200ms 지연과 더 느린 응답, 속도 보고 누락이 없는 경우도 계산했다.

이 모형은 실제 주행 검증이 아니다. 장애물, 조향, 슬립, 엔코더 고장,
DDS 통신과 실제 모터 가감속 성능을 재현하지 않는다. 불필요한 이진 정지를
줄이는 계산 결과이며, 실제 모든 정지를 없앤다는 보증은 아니다.

## 적용

기존 Goal을 취소한다. 후발 추종 프로그램과 선두 Nav2 주행 launch를 종료한다.
현재 정상인 15RPM 모터 드라이버·센서·AMCL·Bridge·relay는 유지한다.

후발에서 새 선두 파일을 별도 폴더로 설치한다. 이 명령은 프로세스를
시작하거나 arm하지 않는다.

```bash
python3 -B ~/nav2_follow_stabilization/smooth010/deploy_leader_candidate.py --apply
```

선두에서:

```bash
bash ~/leader_diagnostics/nav2_follow_stability_da0ab05848da/start_leader_nav2.bash
```

후발 추종 터미널에서:

```bash
bash ~/nav2_follow_stabilization/smooth010/start_follow.bash 0.1
```

입력 준비 후 장애물 없는 짧은 직선 Goal로 먼저 비교한다. 급회전/알람/
정지 불능이 생기면 전원을 차단한다. 실제 검증 후 새 로그의 주행/정지
전환 수와 간격 변화를 기존 성공 로그와 비교해야 한다.
