# 라이다 SDK 내부 근거리점 진단

현재 모델 G2B(15)의 SDK 모델 표에는 230400bps, 5kHz, 강도8비트, 범위0.28~16m가 기재돼 있다. 현재 follower_hardware.yaml의 해당 값은 일치한다. 일반 G2.yaml 예제의 강도10비트·4kHz로 임의 변경하지 않았다.

설치 SDK /usr/local/lib/libydlidar_sdk.a와 YDLidar-SDK/build/libydlidar_sdk.a의 SHA256은 모두 817597915109725ac7ee65c5a7a15f9b6d93bf49d1646d00c44cffd882fefaf7이다.

SDK는 8비트 강도 점의 원본 거리 하위2비트를 node.is에 저장한다. 상수는 sunlight=3, glass=2이다. 이 플래그가 문제점에 실제로 나타났는지는 아직 확인되지 않았다. SDK의 기존 sun/glass 필터 기본값은 false이며 후보에서도 변경하지 않았다.

lidar_sdk_trace/sdk는 별도 복사본이다. CYdLidar.cpp에서 각도 변환 후·거리 필터 전의 내부점에 SDK_NEAR JSON을 stderr로 기록하는 코드만 추가했다. 원본 ROS 드라이버 소스는 그대로 복사해 별도 정적 SDK와 링크했다. 설치·기존 바이너리 덮어쓰기는 하지 않는다. 로그는 source_ns, 원본 점 번호, 각도, 거리, 원본거리 정수, 강도, 잡음플래그, 모델, 필터 활성 상태를 포함한다.

run_lidar_sdk_trace.py --run --seconds 90은 Domain10 최신 비무장·피드백영속도를 확인한 뒤 기존 라이다 프로세스가 정확히1개인지 확인한다. 기존 인수와 params-file을 보존하고 해당 라이다만 SIGINT로 종료한다. 포트 해제를 확인한 뒤 진단 실행파일을 같은 인수로 실행한다. 지정 시간이 지나면 SIGINT 종료하고 원래 명령으로 exec 복원한다. 종료 실패나 포트 사용 중이면 중복 실행하지 않는다. 원래 명령은 logs/lidar_sdk_trace_restore_command.json에도 저장한다.

라이다 중단 동안 스캔이 잠시 끊긴다. 로봇은 정지 상태를 유지하고 이 진단 중 주행 시험을 실행하지 않는다. EKF·AMCL·TF·모터 프로세스 및 필터·보호 조건은 수정하지 않는다. 복원된 라이다를 실행하는 터미널은 유지한다.

## 2차 진단

첫 실측 로그 lidar_sdk_trace_1793619284382727029.log: SDK_NEAR 6점 모두 noise_flag=0, 거리0.287~0.429m. 시작 직후 체크섬 오류1회가 있었지만 그 뒤 근거리점과 동시 오류는 기록되지 않았다. sun/glass 표시 필터만으로 이6점을 제거할 근거가 없다. ROS LaserScan 배열 생성 전 단계에 근거리점이 존재했다.

복원 드라이버 시작 로그에는 연속 체크섬 오류 후 8→0→16→8비트 자동 전환이 보였다. SDK는 m_AutoIntensity=true일 때 연속 오류2회마다 형식을 바꾼다. 이 시작 현상과 90초 중의 근거리점은 별도 문제일 수 있다.

추가된 --fixed-intensity 옵션은 진단 드라이버에만 auto_intensity=false를 전달한다. intensity_bit=8인지 검사한 뒤 시작하며, 체크섬 검사·거부는 유지한다. 기존 드라이버 복원 시 기존 설정으로 돌아간다. 필터·거리 하한·주행 조건은 바꾸지 않는다.

추가 SDK_PACKET_NEAR 기록은 모델15·거리0.28~0.60m의 디코딩된 점을 포함한 패킷 hex를 저장한다. analyze_lidar_packets.py는 해당8비트 패킷을 별도로 읽어 헤더·길이·XOR체크섬 및 거리/강도/잡음표시가 SDK와 일치하는지 확인한다. 정상·바이트변조·잘림·잘못된헤더 테스트4개 통과. 패킷 체크섬 통과만으로 센서 측정의 물리적 정확성을 보장하지 않는다.

## 범위 초과 예외 수정 후보

2차 실측 로그 lidar_sdk_trace_1793619859208544878.log는 intensity_bit=8, auto_intensity=false를 확인했다. 원본 근거리점14개 모두 독립 체크섬 검사 통과, SDK 거리/강도/표시값과 일치. 광학 표시 모두0. 근거리값은 자동 비트 전환 없이도 발생한다.

별도 복사 SDK의 Pack에 수신 당시 intensityBit를 저장하고 parsePoints가 해당 패킷의 형식을 사용하도록 수정했다. calcCheckSum과 parsePoints에 선언된 표본 수·형식과 실제 길이 검사를 추가했다. 이미 저장된8비트 패킷이 현재16비트로 잘못 해석되는 경로를 차단한다. 체크섬 검사와 근거리점은 유지한다.

실측 패킷을 이용한 C++ 테스트: 정상 체크섬, 잘린 체크섬 입력 거부, 저장 후16비트로 전환, 저장된 잘린 패킷 거부, 자동8→0전환 후 저장된8비트 패킷 처리 통과. 실제 serial connect 호출 없음. Python 독립 디코더 테스트4개 통과.

start_lidar_fixed_candidate.py --run: 보존된 원래 명령을 읽되 실행파일만 수정 후보로 바꾸고 auto_intensity=false를 지정한다. 최신 비무장·영속도 및 빈 포트를 요구한다. 기존 노드를 종료하지 않는다. 시스템 SDK/실행파일은 여전히 수정하지 않았다. 새 실행 터미널을 유지한다. 이 후보는 충돌 경로 수정이며 근거리 순간 검출을 해결했다는 뜻은 아니다.
